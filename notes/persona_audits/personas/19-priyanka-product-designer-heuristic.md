## Report

**Evaluator:** Priyanka Rao, Senior Product Designer

**Overview:** CLAWMARKS is a research curation tool for AI-generated artwork from a LoRA
hyperparameter search. It has genuine analytical depth — the coverage map, solution map,
redundancy clustering, and comparison tools reveal a thoughtfully designed system for exploring a
search space. But that depth is buried under implementation vocabulary, zero onboarding,
inconsistent terminology across pages, and a pattern of dumping raw system state at the user
instead of guiding them. A newcomer landing on the gallery page has no idea what "uncanny scan"
means, what "MAP-Elites cell" refers to, or which of the 14 navigation options they should visit
first. The tool rewards domain expertise but actively excludes everyone else.

### 1. First-Contact Test

The landing page (`scan.html`) shows "CLAWMARKS uncanny scan" as the heading and "Browse and
curate AI-generated artwork from this LoRA search" as the subtitle. A newcomer understands there
are images and they can be browsed. That's it. What's missing:

- **No explanation of what CLAWMARKS is for.** The subtitle assumes you already know what a
  "LoRA search" is. A 30-second orientation — "This tool helps you explore and curate artwork
  generated by an AI training search, finding the most interesting and diverse results" — would
  cost one paragraph and fix the entire first impression.
- **The nav button "TRENT_V3_EPOCH4/FREEFORM1" is meaningless to outsiders.** It's an internal
  expedition/leg identifier with no human-readable label.
- **The "Guide" button appears to do nothing.** I clicked it and no modal, overlay, or page
  change appeared. If it's a tooltip toggle, it needs to be visually obvious. If it's broken, it
  should be fixed or removed. This is the one element a newcomer would naturally reach for, and it
  fails silently.
- **No visual hierarchy draws attention to the content.** The page opens with a wall of filter
  controls (Sort, Type, Category, Prompt, Similarity range, Search, picked/favorited checkboxes)
  before the user has any reason to filter. The image grid is the real content; the filters should
  be collapsed or secondary by default.

**Heuristic violated:** Match between system and the real world (the system talks about itself in
implementation terms, not the user's task), Help and documentation (Guide is broken or invisible).

### 2. Information Architecture

The navigation mixes two vocabularies without acknowledging the split:

- **Task-oriented labels** (what the user wants to do): "Browse all images," "Choose between two
  images," "Find near-duplicate groups," "See which prompts are running out."
- **Implementation-oriented labels** (what the algorithm does): "Explore image neighborhoods"
  (this is a UMAP scatter plot), "Find gaps in the image space" (this is a coverage/void map),
  "Check taste-model readiness" (this is a preference classifier status page).

Worse, the jump-to dropdown and the status page link list don't match. The status page links to
"scan gallery," "solution map," "redundancy clustering," "coverage map," "novelty decay,"
"lineage view," "archive," "preference ranking," "preference status," "explore," "seed browser,"
"compare," "cockpit," and "runs" — 14 links, flat, no grouping. The dropdown has 14 options, also
flat. Neither organizes these into logical groups like "Browse & Curate," "Analyze," and
"Configure & Run."

The header also creates confusion: on every page, the left side of the top bar shows the page's
task label (e.g., "Choose between two images"), but the dropdown still shows "Choose between two
images" as selected — so the header and the dropdown are saying the same thing redundantly, while
the actual page heading says something different ("Compare").

**Heuristic violated:** Consistency and standards (two naming systems coexist), Match between
system and the real world (implementation names in user-facing navigation).

### 3. Progressive Disclosure

Several pages dump their full complexity on arrival:

- **Elite Archive:** Opens with a dense paragraph explaining MAP-Elites, quartiles, gold-bordered
  vs. blue-bordered cells, DINOv2 scoring, and population bins — all before the user has seen a
  single image. This should be collapsed to a one-sentence summary ("One best image per region of
  the search space") with an expandable "How this works" section.
- **Coverage / Void Map:** Shows an 8x8 heatmap grid AND a full 64-row raw data table below it,
  with every cell's exact faithfulness/novelty range spelled out to 15 decimal places. The table
  is redundant with the grid and adds visual noise. The "F" labels on frontier cells are
  unexplained without hovering.
- **Solution Map:** The evidence list shows all 50 images with raw filenames
  (`gen1_explore_1_seed214599 gen 1`). This list is not useful until the user selects a region on
  the scatter plot; it should be hidden or collapsed until a selection exists.
- **Generation Cockpit:** Four "Mission" cards, a recipe form with prompt/seed/strength controls,
  an evidence sidebar, and trial record tabs — all visible at once. The mission cards are
  well-designed, but the form below them is overwhelming on first load.

**Heuristic violated:** Aesthetic and minimalist design (visible system dialogue should focus on
relevant information), Progressive disclosure (complexity should be revealed on demand).

### 4. Consistency

Concrete inconsistencies across pages:

1. **"Taste model" vs. "preference classifier."** The navigation says "Check taste-model
   readiness." The page heading says "Preference classifier status." The page text says
   "preference pairwise model." Three names for the same concept on one page.
2. **Duplicate "Choose between two images."** The jump-to dropdown lists "Choose between two
   images" twice — once in the middle of the list and once at the very end. This is a bug, not a
   design choice.
3. **Page heading vs. nav label mismatch.** The nav dropdown says "Explore image neighborhoods"
   but the page heading says "Solution map." The nav says "Find gaps in the image space" but the
   heading says "Coverage / void map." The nav says "Build one image trial" but the heading says
   "Generation cockpit." Every page has this disconnect, forcing the user to reconcile two names
   for the same thing.
4. **Status page links use different names than the dropdown.** Status links to "scan gallery"
   (dropdown: "Browse all images"), "redundancy clustering" (dropdown: "Find near-duplicate
   groups"), "archive" (dropdown: "Best images by area"). The same page is called something
   different depending on how you navigate to it.
5. **Information button placement.** Some pages have the "i" button next to the heading (Elite
   Archive, Solution Map), others have it inline with filter labels (Browse gallery), and some
   have multiple "i" buttons scattered without clear grouping. The "picked only" and "favorited
   only" checkboxes on the gallery each have their own "i" button, while the Category dropdown's
   "i" button explains "MAP-Elites cell" — a term not used anywhere else on that page.

**Heuristic violated:** Consistency and standards (same concept named differently across
contexts), Recognition over recall (user must remember which name maps to which page).

### 5. Error Prevention and Recovery

1. **Lineage Tree and Predicted Preference are dead-end placeholders.** Both pages show a
   text-only explanation of why they're empty, with no visual indicator that they're placeholders
   (no icon, no "coming soon" badge, no grayed-out state). The Predicted Preference page exposes a
   full filesystem path and tells the user to run a Python command
   (`python -m clawmarks.search.preference_pairwise_model`). A newcomer cannot act on this.
   **Fix:** Show a styled placeholder card with a plain-language explanation ("This feature needs
   50 image comparisons before it can work. You currently have 0. [Compare images →]") and hide
   the filesystem path and command.
2. **The "Retrain now" button on Preference Status has no cost warning.** Unlike "Generate" (seed
   browser) and "Back up and launch" (search runs), which both show "SPENDS MONEY" badges,
   "Retrain now" appears clickable with no indication of cost or consequence.
3. **Gallery filter state is invisible.** If a user sets a filter and navigates away, there's no
   visual indicator on return that filters are active. A dismissed filter could silently hide
   images the user expects to see.

**Heuristic violated:** Error prevention (users can hit dead ends with no path forward), Help
users recognize, diagnose, and recover from errors (placeholder pages show raw system state
instead of actionable guidance).

### Top 5 Prioritized Findings

1. **No first-contact orientation.** Every newcomer hits the same wall: jargon-heavy subtitle,
   broken Guide button, no "what is this" explanation. Violates *Match between system and the
   real world* and *Help and documentation*. **Fix:** Add a 2-3 sentence welcome banner below the
   heading. Fix or remove the Guide button. **Effort: cheap.**
2. **Inconsistent page naming (nav dropdown vs. heading vs. status links).** Three different names
   for the same page depending on navigation path. Violates *Consistency and standards* and
   *Recognition over recall*. **Fix:** Pick one name per page and use it everywhere. **Effort:
   cheap.**
3. **Placeholder pages expose raw system state.** Filesystem paths, Python commands, and
   implementation details on Lineage Tree, Predicted Preference, and Preference Status pages.
   Violates *Help users recognize, diagnose, and recover from errors* and *Match between system
   and the real world*. **Fix:** Replace raw paths/commands with plain-language status messages
   and actionable next-step links. **Effort: cheap.**
4. **Dense information dump on analytical pages.** Elite Archive, Coverage Map, and Solution Map
   all open with multi-paragraph technical explanations and full data tables before the user has
   context. Violates *Aesthetic and minimalist design* and *Progressive disclosure*. **Fix:**
   Collapse explanatory text to one sentence with an expandable "How this works" toggle; hide raw
   data tables behind a "Show raw data" button. **Effort: medium.**
5. **Duplicate "Choose between two images" in dropdown.** A straightforward bug that undermines
   trust in the tool's polish. Violates *Error prevention*. **Fix:** Remove the duplicate entry.
   **Effort: cheap.**

**Highest-leverage fixes (cheap changes with outsized payoff):** Findings 1, 2, and 3 are all
cheap and collectively transform the experience from "opaque to outsiders" to "welcoming and
navigable." The orientation banner alone would cut first-contact confusion by half. The naming
consistency fix eliminates a recurring cognitive tax on every page visit. The placeholder cleanup
removes the most embarrassing moments for anyone showing this tool to collaborators or investors.

Status: DONE
